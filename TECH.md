# Legion — технический стек (финальные решения)

## Продукт

**Legion** — доп.защита от фишинговых страниц-однодневок.
Не замена антивируса. Предупреждение только после подтверждённого риска.

## Принцип

Только лучшие и надёжные решения. Скорость и приватность сохраняем архитектурой
(3 ступени + кэш), а не упрощением критичных слоёв.

## Зафиксированный стек

| Слой | Решение |
|------|---------|
| Клиенты | Chrome / Edge / Brave (MV3) |
| Backend | Python 3 + FastAPI + Uvicorn, по умолчанию localhost:8787 |
| Этап 1 | Локальный whitelist |
| Этап 2 | Локальный blacklist **+ Google Safe Browsing Lookup API v4** |
| Этап 3a | Эвристики + brand spoof (бренд ≠ домен) |
| Этап 3b | LLM (OpenAI-compatible) только на «сером» риске |
| Деплой | Школа/локальная защита — localhost; главная защита — хостинг по необходимости |
| Дизайн | Параллельно у команды; логотип подменим без ломки логики |

## Протокол

```
whitelist (домен+поддомены) или exactDomains? → safe
кэш вердикта по содержимому? → отдаём сохранённый
local blacklist OR Safe Browsing hit? → WARN
нет формы с ПДн? → safe «угроз не обнаружено»
эвристики текста (всегда) + brand spoof + lookalike
  brand spoof + критичные поля + подтверждение → WARN
  высокий риск → WARN
  критичные поля + cross-origin → WARN
  иначе жёлтый tier A/B или safe
  серый риск + LLM ключ → LLM → WARN/тишина
```

Сетевые вызовы идут **после** кэша вердикта, health backend кэшируется на 30 с,
ответы Safe Browsing — на 10 мин. Наружу уходит только origin + path, без query.

## Ключи (backend/.env)

- `SAFE_BROWSING_API_KEY` — Google Cloud, Safe Browsing API
- `LLM_API_KEY` + `LLM_BASE_URL` + `LLM_MODEL` — когда появится ключ

Секреты не кладём в расширение.

## Хостинг

Сейчас: `127.0.0.1:8787`.
Если на главной защите потребуют интернет — поднимем тот же FastAPI на VPS/Cloud Run
без смены протокола расширения (только URL в настройках).
